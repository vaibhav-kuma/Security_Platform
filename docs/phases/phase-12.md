Implement the central security-analysis engine that transforms scanner output into trustworthy observations and findings. Create separate Observation and Finding concepts so that an observation means something suspicious or relevant was detected while a finding represents a security issue supported by sufficient evidence. Implement evidence collection for HTTP requests and responses, screenshots, DNS results, TLS information, APK artifacts, static-analysis results, runtime observations, JSON, text, and metadata, along with SecretRedactor, PIIRedactor, CredentialDetector, and EvidenceSanitizer components that remove secrets and unnecessary sensitive information before storage or display. Build FindingCorrelationEngine and deduplication logic based on normalized asset, vulnerability type, location, parameter, and rule identity, and correlate evidence across scanners, methodology test cases, domains, web applications, APIs, APKs, and runtime data. Separate severity from confidence and support very_low, low, medium, high, and very_high confidence, with statuses including open, needs_review, confirmed, false_positive, duplicate, accepted_risk, and resolved. Integrate CVSS scoring and CWE/OWASP mappings where appropriate and add a ManualReviewQueue for ambiguous observations. The platform must never convert a heuristic observation directly into a confirmed critical issue without sufficient evidence, and it must preserve the distinction between "not detected" and "secure."
