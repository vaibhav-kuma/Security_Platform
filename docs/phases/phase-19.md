Implement a versioned Security Knowledge Base that allows the platform to evolve independently from its core application logic. Model and manage versioned OWASP WSTG definitions, OWASP API Security definitions, MASTG and MASVS mappings, CWE metadata, CVSS metadata, detection rules, remediation content, methodology test cases, and technology fingerprints as separately versioned rule or knowledge packs. Each rule should define identity, version, name, methodology, category, target types, prerequisites, evidence requirements, severity guidance, confidence guidance, references, and applicable detection behavior. Build a secure knowledge-pack update pipeline with download, integrity verification, schema validation, security validation, installation, activation, rollback, and audit logging, ensuring untrusted packs are never executed blindly. Allow methodology versions to coexist so historical scan results remain reproducible and understandable even after newer methodology versions are installed. Provide a knowledge-base management UI and CLI so administrators can inspect installed versions, enable or disable packs, and understand what methodology version was used for each scan.
