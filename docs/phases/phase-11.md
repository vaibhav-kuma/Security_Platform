Implement the API security assessment engine for authorized REST, JSON, GraphQL, OpenAPI, and Swagger targets and integrate it with the WSTG methodology framework and a versioned OWASP API Security methodology layer. Build OpenAPI and Swagger importers, endpoint inventory, HTTP method inventory, parameter and schema extraction, authentication detection, authorization context modeling, object identifier analysis, role and privilege analysis, API inventory analysis, rate-limit observations, and controlled security-test planning. Represent API structures as API → endpoints → methods → parameters → schemas → authentication → responses, and create test cases and detection rules for relevant API security categories such as object-level authorization, authentication, property-level authorization, resource consumption, function-level authorization, sensitive business flows, SSRF-related behavior, security misconfiguration, API inventory management, and unsafe external API consumption. Tests must be evidence-driven and must distinguish observations from confirmed vulnerabilities, especially for authorization-related behaviors. Support anonymous, normal-user, privileged-user, administrator, and service-account contexts only when explicitly configured and authorized by the project. Do not store plaintext credentials, do not test out-of-scope APIs, and require controlled limits for active testing. Add full unit, integration, and methodology-mapping tests.
