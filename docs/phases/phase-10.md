Implement the methodology layer that turns OWASP Web Security Testing Guide guidance into a versioned, executable test-planning system without hard-coding methodology logic into individual scanners. Create Methodology, MethodologyVersion, TestCase, TestCaseRun, DetectionRule, TestPlanner, and CoverageEngine models and store methodology definitions as versioned data or rule packs. Organize web test cases across information gathering, configuration and deployment management, identity management, authentication, authorization, session management, input validation, error handling, cryptography, business logic, client-side testing, and API/web-service-related testing as applicable to the chosen WSTG version. Each test case must declare its identifier, name, description, category, supported target types, prerequisites, passive/active mode, safe-mode compatibility, evidence requirements, detection rules, and references. The TestPlanner must dynamically select applicable test cases based on target type, discovered technology, application model, authentication model, API model, project scope, and testing profile, while correctly marking tests as Tested, Not Tested, Needs Review, or Not Applicable. Create a methodology coverage dashboard and never treat incomplete coverage as proof of security. Add tests proving that methodology selection is deterministic, that unavailable prerequisites suppress incompatible tests, and that methodology versions can evolve without rewriting core scanner code.
